# new-tab

A Chrome extension (Manifest V3) that replaces the new tab page with a
keyboard-first view of the user's bookmarks: folders as cards packed into
columns, a filter that always has the cursor, and every action reachable from
the keyboard. Agents maintain this repo.

## Principles

- No build step and no dependencies. Plain HTML, CSS and JavaScript that Chrome
  loads as is. Ask the user before adding a library.
- No network access. Bookmarks and favicons come from Chrome's own APIs, and
  nothing leaves the machine.
- Request only the permissions the page uses.
- Never bind keys Chrome keeps for itself (⌘T, ⌘W, ⌘N, ⌘L, ⌘1–⌘9 and the
  like). They never reach the page.
- Letters and digits always type into the filter. Actions use arrows, Enter,
  Tab, Esc, or ⌘/⌥ chords, and rare actions go in the ⌘K menu. Nothing
  destructive sits on a single key, and every change can be undone.
- Ignore key events while an input method is composing (`event.isComposing`),
  so typing Chinese never triggers an action.

## How it fits together

- `boot.js` reloads the page once (`location.search = 'r'`) so it takes keyboard
  focus from the address bar. Of the approaches tried, this and reopening the
  tab worked; this one keeps the same tab. Don't remove it.
- `pinyin.js` is generated by `scripts/generate-pinyin.swift`. Don't edit it by
  hand.
- `chrome.bookmarks.move` counts the destination index before removing the node,
  so moving a link down within its folder needs the neighbor's index plus one.

## Testing

Agents can't load or reload the extension. Ask the user to load this folder at
`chrome://extensions` (Developer mode, then Load unpacked), and after each
change to click the reload icon on the extension's card and open a new tab.
